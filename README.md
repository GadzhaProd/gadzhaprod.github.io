# Gadzha — личный сайт

Одностраничный сайт-визитка AI Product Builder.
Позиционирование: **«Когда задачи ещё нет в ТЗ — я уже собираю первый рабочий результат»**.

**Аудитория (решено 14.08.2026):** действующие компании с ручной рутиной или планами
на AI — не стартапы на стадии идеи. Рынок международный, поэтому **английский главный**:
он открывается по умолчанию, статические тексты в разметке английские, русский включается
только если браузер прямо просит русский. Цель сайта — заказы (найм вторичен).

Без сборки, без зависимостей, без бэкенда. Открывается как есть, разворачивается куда угодно.

## Два языка

Русский и английский живут в **одном** документе: `i18n.js` хранит обе версии,
разметка одна. Правки текста делаются только в `i18n.js` — в `index.html`
лежат лишь значения по умолчанию на случай, если JS не выполнится.

В разметке:

| Атрибут | Что делает |
|---|---|
| `data-i18n="ключ"` | подставляет строку как текст |
| `data-i18n-html="ключ"` | как HTML — только для строк с `<br>`, `<em>`, `<a>` |
| `data-i18n-aria="ключ"` | подставляет в `aria-label` |
| `data-i18n-mail="адрес"` | собирает `mailto:` с темой на нужном языке |

Язык выбирается так: `?lang=ru|en` в адресе → сохранённый выбор → язык браузера → **английский**.
Выбор запоминается в `localStorage`, `<html lang>` и мета-теги обновляются вместе с текстом.

Ссылки вида `?lang=en` можно давать напрямую — они открывают нужную версию сразу.

**Добавляя текст:** заведите ключ в **обеих** секциях `ru` и `en`. Проверить,
что ничего не забыто, можно в консоли — этот скрипт ищет кириллицу
на английской версии и должен вернуть пустой список:

```js
GadzhaI18N.set('en');
[...document.querySelectorAll('body *')].flatMap(e=>[...e.childNodes])
  .filter(n=>n.nodeType===3 && /[А-Яа-яЁё]/.test(n.nodeValue)).map(n=>n.nodeValue.trim())
```

**Осторожно с CSS:** обёртки `<span>`, добавленные ради перевода, могут попасть
под старые селекторы вида `.block span { … }`. Так уже случилось с шагами в CTA —
правило красило и ломало перенос у текста. Целиться в `:first-child`, а не во все `span`.

Секции: hero с конвейером → `[01]` с чем прийти → `[02]` что собираю →
`[03]` разбор задачи (Build Radar) → `[04]` что собрал → `[05]` как я работаю → `[06]` CTA.

## Две интерактивные штуки

### Build Radar

Шесть типов задач (AI-прототип, лендинг, внутренний инструмент, фича, автоматизация,
внедрение AI). Ключ `adopt` заменил бывший `demo` — «демо для питча» это язык стартапов,
а аудитория теперь действующие компании. Выбор показывает разбор по четырём режимам, главный риск,
первый результат и горизонт итерации — и одновременно перестраивает конвейер в hero
и меняет состав частиц на фоне.

Тексты разборов лежат в `i18n.js` (`tasks.*`), в `radar.js` осталась только логика
и объект `FIELD`: `mix` (доли четырёх сигналов) и `tempo` (скорость потока частиц).

### Live Build Pulse — снята со страницы

Код сохранён, но не подключён. Описание ниже актуально, если секцию вернут.

Читала события трёх активных публичных репозиториев через GitHub REST API
и раскладывает их по четырём режимам: push → build, pull requests → quality,
create/release → delivery, issues → discovery.

**Почему не общая лента `/events`:** анонимному клиенту GitHub отдаёт в ней почти
исключительно `PushEvent` и `CreateEvent` — событий pull request и issues там нет вообще,
и три режима из четырёх всегда показывали бы ноль. Проверено на живом ответе:
92 push, 6 create, 2 delete из 100. Поэтому источник — ленты конкретных репозиториев
(`REPOS` в начале `assets/js/pulse.js`).

Ограничения и как они обрабатываются:

- лимит без авторизации — 60 запросов в час на IP; ответ кэшируется в `localStorage` на 10 минут;
- упавший репозиторий не ломает секцию — его события просто не попадают в выборку;
- если API недоступен целиком, включается локальный fallback-профиль, **явно подписанный
  как офлайн** — он не выдаёт себя за живые данные;
- имена репозиториев вставляются через `textContent`, а не `innerHTML`.

## Поле частиц

Фоновый canvas — не декорация: доли цветов задаёт выбранный в Build Radar тип работы
(раньше их задавала ещё и секция Live Build Pulse, теперь она снята). Частицы текут слева направо
через пять створов — это тот же конвейер, что и в hero.

Плотность считается от площади экрана и ограничена сверху; анимация останавливается,
когда вкладка неактивна. При `prefers-reduced-motion` рисуется один статичный кадр.

API: `GadzhaField.setMix({build, review, ship, probe})`, `.setTempo(k)`, `.burst(kind)`.

**Пробовали и отказались:** поле течения с накоплением следов (flow field, как на
chemical-pink.vercel.app). Технически работало и держало контраст 8,4:1, но на полный
экран читается как биологическая масса — мелкие извивающиеся нити с яркими головками.
Для фона под текстом не годится.

## Запуск

Любой статический сервер:

```bash
python3 -m http.server 4891
```

Затем откройте `http://localhost:4891`.

Через `file://` страница тоже откроется — внешних запросов на ней больше нет.

## Деплой

Каталог статический целиком — подойдёт Netlify, Vercel, GitHub Pages, Cloudflare Pages
или обычный nginx. Сборка не нужна, переменных окружения нет.

```bash
npx vercel --prod
```

Единственная внешняя зависимость — шрифты Google Fonts (Unbounded, Golos Text, JetBrains Mono).
Если нужна полная автономность, скачайте их в `assets/fonts/` и замените `<link>` на `@font-face`.

## Технические решения

- **Шрифты с полной кириллицей.** Unbounded (заголовки), Golos Text (текст),
  JetBrains Mono (телеметрия). Ни одного системного шрифта.
- **Доступность.** Skip-link, видимая обводка фокуса, стрелки переключают вкладки радара,
  поддержка `prefers-reduced-motion` и `prefers-contrast`.
- **Адаптив.** Конвейер на узких экранах разворачивается из горизонтального в вертикальный.
- **Кэш.** Ссылки на CSS/JS помечены `?v=N` — увеличьте номер после правок,
  иначе браузеры отдадут старую версию.
