Approach

Result
A clickable first version and an honest list of limits — enough to decide.

[ 05 ]

How I work:
a working piece first.

A working piece first, everything else after. It’s the fastest way to find the direction and decide on facts, not slides.

  • “Let’s make it look good” → “Let’s make something we can show and test”
  • “First a twenty-page spec” → “First a working piece, then a spec grounded in facts”
  • “Design apart, code apart, tests someday” → “One head carries the work from wording to deploy”

To get started you don’t hire anyone or line up four contractors. Nothing falls through the cracks, because there are no gaps.

Some call this vibe coding. For me it’s faster research and building — not a promise to “generate” a product. The scenario, the limits, the code and the result are on me.
